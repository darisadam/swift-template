# Tuist · Simple MVVM

A single-project Tuist app with SwiftUI + `@Observable` view models. Same architecture as the XcodeGen Simple MVVM template, just generated by Tuist instead.

Pick this when you want Tuist's type-safe Swift manifests but don't need module separation yet.

> 💡 Don't know what Tuist, MVVM, or `@Observable` mean? Read `docs/concepts.md` in the swift-template repo first.

## What you see when you run it

Hit `Cmd+R` in Xcode. The Simulator opens and shows a counter screen: a big `0`, three buttons (`−`, Reset, `+`). Tap them, the number changes. That's the example feature — replace it with your own once you understand the layout.

## Guided tour (5 files in 30 seconds)

1. **`Tuist.swift`** — toolchain pin (Swift version). Don't touch.
2. **`Project.swift`** — describes the whole app: the iOS target, deployment targets, sources, tests. Edit when you add a new top-level destination (Mac, Vision Pro) or change bundle ID.
3. **`Sources/App/__APP_NAME__App.swift`** — `@main` entry point.
4. **`Sources/Features/Counter/ViewModels/CounterViewModel.swift`** — the example ViewModel. `@Observable @MainActor`, holds `count`, exposes `increment()`/`decrement()`/`reset()`.
5. **`Sources/Features/Counter/Views/CounterView.swift`** — the SwiftUI view that consumes the ViewModel.

## Try this first (3 beginner exercises)

### Exercise 1: Add a "double" action

1. In `CounterViewModel.swift`:
   ```swift
   func double() { count *= 2 }
   ```
2. In `CounterView.swift`, add a button:
   ```swift
   Button("×2") { viewModel.double() }.buttonStyle(.bordered)
   ```
3. `Cmd+R`.

### Exercise 2: Add a max value

Refuse to increment past 10 (full code in the XcodeGen Simple MVVM README — same logic).

### Exercise 3: Add a second screen

Create `Sources/Features/Greeting/Views/GreetingView.swift`, add a `NavigationLink` from `RootView.swift`.

## Layout

```
Tuist.swift                   # toolchain version pin
Project.swift                 # the app definition (one project, multi-target)
Sources/
├── App/                      # @main + RootView
├── Features/
│   └── Counter/
│       ├── ViewModels/
│       └── Views/
└── Common/Logger/
Tests/                        # XCTest unit tests
UITests/                      # XCUITest
Resources/
├── Assets.xcassets/
└── Plist/
```

## How to run

```bash
./setup.sh                            # installs Tuist, runs `tuist install` + `tuist generate`
open __APP_NAME__.xcworkspace         # Tuist generates a workspace, not just a project
# then Cmd+R in Xcode
```

## Verification

```bash
swiftlint lint --fix --config .swiftlint.yml
swiftlint lint --config .swiftlint.yml

xcodebuild test \
  -workspace __APP_NAME__.xcworkspace \
  -scheme __APP_NAME__ \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
  -skip-testing:__APP_NAME__UITests
```

## Adding a new feature

1. Create `Sources/Features/<Name>/{ViewModels,Views}/`
2. Add `<Name>ViewModel` + `<Name>View`
3. Wire it into `RootView`
4. Add tests in `Tests/`
5. Sources are auto-discovered — no need to run `tuist generate` unless you edit `Project.swift`

## Adding more platforms

Edit `Project.swift` → `destinations` and `deploymentTargets`:

```swift
destinations: [.iPhone, .iPad, .mac, .appleVision, .macCatalyst]
deploymentTargets: .multiplatform(
  iOS: "__DEPLOYMENT_TARGET__",
  macOS: "14.0",
  visionOS: "1.0"
)
```

Then `tuist generate`.

> For Apple Watch or Widget extensions, you'll want **Tuist / Modular MVVM** — separate targets are cleaner when each has its own module.

## When to upgrade to Modular MVVM

When `Sources/Features/` has > 10 folders, or your team grows past 2 developers. The migration is mostly mechanical: move each `Features/<Name>/` folder into a new `Modules/Features/<Name>/Sources/`, add a `Project.swift` for it, and update `Workspace.swift`.
